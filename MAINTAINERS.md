# Maintainers

ML Blueprint is run by students of ACM IIT Mandi.

Maintainers review pull requests, merge them, and answer questions. If you are stuck on
anything, tagging one of us is always fine.


## How to reach us

Open an issue or a [Discussion](https://github.com/ACM-IIT-Mandi/ML-Blueprint/discussions), or
tag a maintainer in a pull request. For anything sensitive, message the ACM IIT Mandi core
team directly.

## Becoming a maintainer

There is no application. If you have had a few pull requests merged and you have been helpful
in reviews, someone will ask you. If you think you have been missed, just say so, that is a
completely reasonable thing to bring up.

## Making decisions

Small stuff: one maintainer approves and merges.

Bigger stuff, like adding a new dependency, changing the folder layout, or changing the
standards: open an issue, give people a few days to respond, then go ahead if nobody objects.

If we disagree and cannot settle it, the maintainers talk it out and take a majority view.

## Handover

Everyone graduates eventually, so before you leave:

1. Find someone to take over what you look after, and add them to the table above.
2. Write a short note in an issue: what is done, what is half done, what you would do next.
3. Add the new person on GitHub (see the setup steps in
   [docs/REPOSITORY_GUIDE.md](docs/REPOSITORY_GUIDE.md)).

Try to overlap by a few weeks rather than handing over on your last day. A project that goes
quiet for one summer is hard to restart.
